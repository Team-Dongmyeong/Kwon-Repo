# RAG 데이터 전략 관련 논의 정리 (질문–답변 보고서)

> 작성 배경: SBERT 키워드 분류 모델 검증 이후, RAG 지식베이스를 4개 소분류(역량부족/취업진로/면접/자기소개서) 중 어디까지 구축할지, 논문 제목과의 정합성은 어떤지에 대한 팀 고민을 질문-답변 형태로 정리한 문서.
> 작성일: 2026-09-12

## 배경

키워드 분류(SBERT) 모델 검증 과정에서, RAG로 실제 차별화를 두려는 4개 소분류(역량부족/취업진로/면접준비/자기소개서) 중 역량부족·취업진로 2개는 이미 표 형태의 구조화된 데이터(추천기업·임금·전망 / 자격증·기술·학과)를 만들어 놓은 상태였음. 반면 면접준비·자기소개서 2개는 "정답"이라 부를 만한 데이터를 만들지 못한 상태로 남아있었고, 이를 어떻게 처리할지에 대한 고민이 있었음.

---

## Q1. API·DB(Supabase) 연동, 키워드·감정 모델 백엔드 연동은 언제 해도 되는가?

**A.** 프론트엔드 결과물을 먼저 완성한 뒤에 연결해도 문제없음. 스키마 설계 등 세부 방법은 아직 정해지지 않았지만, 순서상 후순위로 미뤄도 되는 작업.

## Q2. 면접준비·자기소개서 2개 소분류는 역량부족·취업진로와 같은 방식(표 형태 데이터셋)으로 만들어야 하는가?

**A.** 아니오. 역량부족(자격증/기술/학과)과 취업진로(연봉/전망/추천기업)는 **객관적 사실 데이터**라서 표로 정리할 수 있지만, 면접준비·자기소개서는 "정답 면접 질문"이나 "정답 자소서 문장"이 존재하지 않는 **코칭 성격의 피드백 영역**이라 같은 형식을 억지로 적용하기 어려움.

**결정 방향**: 면접준비·자기소개서는 별도 표 데이터셋을 구축하지 않고, GPT-4o mini가 감정 분석 결과와 사용자 발화 맥락을 참고해 직접 코칭형 답변을 생성하도록 처리. 대신 확보된 리소스는 역량부족·취업진로 2개 카테고리의 직무 커버리지(현재 IT/SW 위주)를 넓히는 데 집중.

**근거**: 이번 SBERT held-out 평가에서 나온 약점 카테고리 15개 중 다수가 "자기소개서" 라벨(예: 식/음료\|\|직무공통\|\|자기소개서 f1=0.00)이었음 — 자기소개서 관련 발화 자체가 카테고리 불문 전반적으로 데이터가 얇고 패턴이 불명확하다는 게 실측으로도 확인됨. 즉 "표 데이터 부재"뿐 아니라 "학습 발화 데이터 자체의 성격"에서도 같은 신호가 나타남.

## Q3. 면접·자소서 관련해서 인터넷에 공개된 자료 중 RAG에 추가로 넣을 만한 게 있는가?

**A.** 있음. 아래 2가지를 우선 추천:

- **고용24 "직무별 자소서 작성가이드"**: 워크넷을 통합한 정부 취업 포털 고용24에서 운영하는 직무별 자소서 작성 가이드 페이지.
- **NCS(국가직무능력표준) "직업기초능력"**: 정부가 직무별로 표준화한 능력 체계 — 역량부족 데이터 보강에도 활용 가능.
- (추가) **NCS직업기초능력검사(자가진단, 기업인력애로센터 운영)**: NCS 직업기초능력을 실제로 자가진단해볼 수 있는 공개 설문/검사 도구 — "NCS 외 공개 설문지"를 찾던 부분에 해당하는 자료.

(팀원 병철님께 전달할 쉬운 설명은 아래 부록 참고)

## Q4. RAG 방향("역량부족·취업진로 중심")이 교수님이 정해주신 논문 제목("대화형 인터페이스 기반의 지능형 피드백 시스템의 구현")과 충돌하지 않는가?

**A.** 충돌하지 않음. "지능형 피드백 시스템"은 취업진로 매칭 하나만을 가리키는 좁은 개념이 아니라, 자소서 피드백·면접 피드백·역량 진단 피드백·진로 추천 피드백을 모두 포괄하는 상위 개념. 4개 영역을 대화형 인터페이스로 제공하는 지금 구조(2개는 RAG 기반 사실 피드백, 2개는 감정 분석 결합 GPT 생성 피드백)가 오히려 이 제목과 자연스럽게 맞아떨어짐. 논문에서 "왜 4개 영역을 다르게 처리했는지"의 설계 근거로 그대로 활용 가능.

## Q5. RAG 데이터가 2개 영역뿐인데 이대로 진행해도 되는가? (일반 LLM과의 차별화가 될지 걱정)

**A.** 그대로 진행해도 됨. 차별화 포인트는 "4개 영역 모두 RAG 데이터를 갖췄다"가 아니라, **"객관적 사실 정보가 필요한 영역엔 RAG로 환각을 줄이고, 정성적 피드백이 필요한 영역엔 감정 분석 결과를 결합한 맞춤 생성을 한다"는 하이브리드 설계** 자체. 이 설계 논리가 명확하면 데이터가 2개 영역뿐이어도 논문상 충분히 방어 가능.

### 참고 — RAG 처리 흐름 요약

1. 역량부족·취업진로 표 데이터를 자연어 문장 청크로 변환
2. 임베딩 후 Supabase pgvector에 저장
3. 사용자 발화 입력 시 SBERT로 대분류/중분류/소분류 분류
4. 분류 결과로 필터링된 벡터 검색(코사인 유사도)으로 관련 청크 top-k 검색
5. 검색된 청크 + 사용자 발화 + 감정 분석 결과를 GPT-4o mini 프롬프트에 결합해 최종 답변 생성

(면접·자소서는 3~4단계 없이 바로 5단계로 진행 — RAG 검색을 거치지 않고 GPT가 직접 생성)

## 최종 방향 정리

1. RAG 지식베이스는 **역량부족·취업진로 2개 소분류만 우선 구축**하고, 면접·자소서는 GPT-4o mini 직접 생성(감정 분석 결과 결합)으로 처리한다.
2. 남은 데이터 작업 리소스는 (a) IT/SW 외 나머지 대분류의 역량부족·취업진로 커버리지 확장, (b) NCS·고용24 등 공개 데이터로 보강에 투입한다.
3. 논문에서는 "4개 영역을 사실 기반(RAG)과 코칭 기반(GPT 생성)으로 나눠 처리했다"는 설계 논리를 명시해, 논문 제목("지능형 피드백 시스템")과의 정합성 및 일반 LLM과의 차별화 근거로 사용한다.

**1. 고용24 "직무별 자소서 작성가이드"**

- 링크: https://www.work24.go.kr/wk/r/d/1150/retrieveSelfintroWriteGuideViewList.do
- 할 일: 여기 들어가서 우리가 다루는 직무(대분류/중분류)에 해당하는 가이드 내용이 있는지 찾아보고, 있으면 캡처하거나 텍스트로 정리해서 공유해주면 됨.

**2. NCS(국가직무능력표준) "직업기초능력"**

NCS는 정부가 "이 직업은 어떤 능력이 필요한지"를 표준화해서 정리해둔 자료예요. 우리가 이미 만든 "역량부족" 데이터(자격증, 기술, 필요 지식 등)랑 성격이 비슷해서, 우리가 아직 안 만든 직무 카테고리의 데이터를 채우는 데 참고하기 좋아요.

- 링크: https://www.ncs.go.kr/th03/TH0302List.do?dirSeq=121
- 할 일: 우리가 다루는 대분류/중분류에 맞는 직업기초능력 항목을 찾아서, 기존 "역량부족" 표 형식(자격증/기술/학과/필수지식)에 맞게 정리

**3. (추가) NCS직업기초능력검사 — 자가진단 사이트**

NCS 능력을 실제로 "테스트"해볼 수 있는 공개 설문/검사 사이트예요. NCS 자체는 "이 직업엔 이런 능력이 필요하다"는 설명 자료이고, 이건 "내가 그 능력을 얼마나 갖췄는지" 체크해보는 설문이라 성격이 조금 달라요. 나중에 사용자에게 "역량 진단 설문"을 만들 때 문항 구성 참고용으로 쓸 수 있어요.

- 링크: https://job.kosmes.or.kr/sportSvc/ncsInspctInfo/info.do
