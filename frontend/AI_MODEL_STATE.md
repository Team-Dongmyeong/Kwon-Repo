## 1. 현재 상태

- **SBERT(키워드 분류)**: `snunlp/KR-SBERT-V40K-klueNLI-augSTS` 파인튜닝, 148개 결합 라벨(대분류\|\|중분류\|\|소분류) 분류, `BatchHardTripletLoss` 사용. Held-out 평가 완료 — 대분류 95.95%/중분류 72.03%/148-way 57%(macro-F1 0.42). 약점은 식/음료·디자인 계열(데이터 절대량 부족이 원인). `SentenceLabelDataset` 재학습(`_v2`) 시도했으나 개선 없음 확인.
- **KcELECTRA(감정 분류)**: `beomi/KcELECTRA-base-v2022` 파인튜닝, 7-class 한국어 구어체 감정 분류. 재학습 및 held-out 평가 완료.
  - 전체: accuracy 60.4% / macro-F1 0.56 / weighted-F1 0.60
  - 잘 맞추는 감정: 중립(F1 0.76), 행복(F1 0.70), 슬픔(F1 0.62)
  - 약한 감정: 혐오(F1 0.40), 놀람(F1 0.42), 공포(F1 0.47)
  - 결론: 중립/행복/슬픔은 자신 있게 사용 가능, 혐오/놀람/공포는 보수적으로 취급.
- **GPT-4o mini 대화 엔진 연동 (경민 담당) — 완료**: FastAPI 백엔드(`backend/main.py`)에서 OpenAI `gpt-4o-mini` 모델로 실제 API 호출을 구현하고, 세션별 대화 히스토리를 시스템 프롬프트(`backend/prompts.py`, 마음잇기 상담사 페르소나)와 함께 매 요청에 포함시켜 컨텍스트를 유지하는 구조를 완성. 프론트엔드(`Chat.jsx`, 세션 여러 개를 좌측 목록으로 관리하는 Claude/Gemini 스타일 UI)와 연결하고, Vercel(프론트)·Render(백엔드) 배포까지 완료되어 로컬 명령어 없이 실서비스 주소에서 실제 동작을 확인함.
  - **단, 감정(KcELECTRA)·키워드(SBERT) 분석 결과는 아직 이 대화 엔진에 연결되지 않은 상태** — 현재 GPT는 시스템 프롬프트(상담사 페르소나)만으로 응답을 생성 중이며, 세션별 감정/키워드 분석·태깅은 다음 단계.
  - RAG(역량부족/취업진로 지식베이스)도 아직 이 대화 엔진에 연결되지 않음 — 현재는 순수 GPT-4o mini 프롬프트 엔지니어링만으로 응답.
  - 세션/메시지 데이터는 Supabase 연동 전까지 프론트엔드 localStorage에만 저장되는 임시 구조(자세한 내용은 `PROJECT_STATE.md` 참고).
- **RAG 지식베이스 범위**: 4개 소분류(역량부족/취업진로/면접준비/자기소개서) 중 역량부족·취업진로 2개만 구조화 데이터로 구축. 면접·자소서는 RAG 없이 GPT-4o mini가 직접 답변 생성.
- **자소서/면접 프롬프트 설계**: 고용24 자소서가이드에서 추출한 5가지 질문 유형 프레임워크를 GPT 시스템 프롬프트에 고정 반영하는 설계는 완료했으나, 실제 GPT 호출에는 아직 세부 반영 안 됨 — 현재 `SYSTEM_PROMPT`는 상담사 페르소나 위주, 5유형 프레임워크 세부 반영은 다음 단계.
- **RAG 인프라**: Supabase + pgvector 계획만 있고 코드 미착수. 병철이 로그인용 Supabase 프로젝트를 이미 구축해둔 상태라, 경민이 그 프로젝트에 합류(팀원 초대)한 뒤 진행 예정.
- 세부 근거·수치는 Project Knowledge의 `AI_모델_학습_및_검증_전략.md`, `RAG_데이터_전략_논의_정리.md`, `자소서_답변_생성_프롬프트_설계.md`, `최종 방향 정리병철이 전달 문서.md` 참고.

## 3. 주요 결정 사항

- SBERT 재학습으로도 식/음료·디자인 약점이 개선되지 않아, 다음 단계는 해당 카테고리 한정 GPT 표적 데이터 증강으로 확정.
- RAG는 "사실 정보가 존재하는 영역(역량부족·취업진로)에만 적용"으로 범위를 좁힘 — 차별화 근거는 "사실기반/코칭기반 하이브리드 설계" 자체.
- 면접·자소서는 구조화 데이터셋 없이 GPT-4o mini 프롬프트 엔지니어링(5유형 프레임워크 고정 반영)으로 대응.
- 공개 데이터 활용 우선순위: 임금직업포털 → NCS 직업기초능력 → NCS 자가진단.
- KcELECTRA는 중립/행복/슬픔 위주로 신뢰, 혐오/놀람/공포는 보수적으로 취급.
- Google Drive 파일 관리 원칙: `optimizer.pt`, `model.safetensors`, `pytorch_model.bin`은 절대 용량 정리 대상에서 제외.
- **GPT-4o mini 연동 우선순위**: 감정/키워드 분석 결과를 먼저 붙이기보다, 채팅 UI+백엔드+배포 파이프라인을 먼저 통째로 완성하는 쪽으로 진행 — 이제 파이프라인이 완성됐으므로 다음은 분석 결과 연결과 Supabase 영구 저장.
- Supabase는 병철이 이미 만든 로그인용 프로젝트 하나만 사용하기로 결정 — 경민이 별도 계정/프로젝트를 새로 만들지 않고, 팀원 초대를 받아 같은 프로젝트에 `conversations`/`messages` 테이블을 추가하는 방식으로 합류.
