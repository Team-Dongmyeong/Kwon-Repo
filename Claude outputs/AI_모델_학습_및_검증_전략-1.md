# 마음잇기 — AI 모델 학습 및 검증 전략 노트

> 이 문서는: 지금까지 SBERT(직무 키워드 분류) 모델을 실제로 테스트해본 결과와, 왜 다음 단계로 "GPT로 데이터 추가 생성(표적 증강)"을 하려는지를 팀원들이 쉽게 이해할 수 있도록 정리한 문서입니다.
> 최종 업데이트: 2026-09-12

## 1. 우리가 왜 이걸 확인해야 했나

원래 계획은 "사용자와 짧은 대화 → AI가 감정·직무 키워드 분류 → 맞춤 직무/채용정보 추천"이었어요. 그런데 실제로 이 분류 모델(SBERT)이 학습 데이터에서 카테고리별로 데이터 양이 크게 차이 난다는 게 미리 확인됐었습니다(`class_weights.json` 참고). 데이터가 적은 카테고리는 모델이 잘 못 맞출 가능성이 높다는 뜻이라, **실제로 얼마나 정확한지, 어디가 약한지를 직접 테스트**해봐야 했습니다.

## 2. 테스트 방법 (간단 설명)

- 학습에 쓰지 않은 데이터(`test_stratified.csv`)로 "이 문장은 어떤 직무 카테고리에 해당할까?"를 모델이 맞히는지 채점
- 세 가지 단위로 나눠서 확인함:
  - **대분류** (예: IT/SW, 디자인, 식/음료 등 5개 큰 분류) — 가장 큰 틀
  - **중분류** (예: 백엔드개발자, 시각디자이너 등 약 40개) — 좀 더 구체적인 직무
  - **148개 세부 조합** (대분류+중분류+고민유형까지 합친 가장 세밀한 단위)

## 3. 1차 테스트 결과 (기존 모델, GPT로 1차 증강한 데이터로 학습된 모델)

| 단위 | 정확도 |
| --- | --- |
| 대분류 (5개) | **95.95%** |
| 중분류 (~40개) | **72.03%** |
| 148개 세부 조합 | **57%** (macro-F1 0.42) |

**쉽게 말하면**: "이 사람이 IT 직무를 고민하는지 디자인 직무를 고민하는지" 같은 큰 틀은 거의 완벽하게 맞춥니다(96%). "어떤 세부 직무인지"까지 가면 정확도가 떨어지긴 하지만(72%), 그래도 실사용 가능한 수준. 가장 세밀한 단위(148개)에서는 절반 정도만 정확히 맞음.

**약점이 어디 몰려있는지 확인해보니**: 148개 중 성능이 특히 낮은 하위 15개 카테고리를 뽑아보니, **식/음료 계열**(카페·레스토랑매니저, 조리사 등)과 **디자인 계열**(시각디자이너, 편집디자이너, 캐릭터디자이너 등)에 집중되어 있었습니다. 이건 처음에 `class_weights.json`으로 예상했던 "이 카테고리들은 학습 데이터가 적다"는 우려가 실제로 맞아떨어진 것입니다.

## 4. 원인 확인 시도 — 배치 구성 방식 수정 (재학습 실행함)

**가설**: 모델을 학습시키는 방식(`BatchHardTripletLoss`)은 한 번에 묶어서 보는 데이터 묶음(배치) 안에 같은 카테고리 예시가 최소 2개는 있어야 제대로 학습이 됩니다. 그런데 기존 학습 코드는 이걸 랜덤하게만 섞어서 넣고 있었기 때문에, 데이터가 적은 카테고리(식/음료·디자인)일수록 한 배치 안에 같은 카테고리가 우연히 모일 확률이 낮아 제대로 학습이 안 됐을 수 있다고 의심했습니다.

**조치**: `SentenceLabelDataset`이라는 방법으로 배치 구성 방식만 바꿔서 재학습 진행 (`fine_tuned_kr_sbert_148_v2`로 별도 저장, 기존 모델은 그대로 보존).

**재학습 후 재테스트 결과**:

| 단위 | 기존 모델 | 재학습 모델(v2) | 결과 |
| --- | --- | --- | --- |
| 대분류 | 95.95% | 94.60% | 오히려 소폭 하락 |
| 중분류 | 72.03% | 72.28% | 거의 변화 없음 (오차 범위) |
| 식/음료·디자인 약점 카테고리 | f1 0.00~0.40대 | f1 0.00~0.40대 | **개선 안 됨, 같은 카테고리가 그대로 약함** |

## 5. 결론 — 왜 지금 GPT 표적 증강을 해야 하는가

**배치 구성 방식을 고쳐도 약점이 그대로였다는 것은, 원인이 "학습 방식의 사소한 버그"가 아니라 훨씬 단순하고 근본적인 문제라는 뜻입니다: 해당 카테고리의 학습 데이터 자체가 절대적으로 너무 적다.**

실제로 이번에 약점으로 나온 카테고리들의 학습 데이터 개수(support)를 보면 5~18개 수준밖에 안 됩니다. 아무리 학습 방식을 정교하게 고쳐도, 애초에 모델이 "이런 게 식/음료 자기소개서 고민이구나"를 배울 예시 자체가 부족하면 정확히 맞히기 어렵습니다. 사람도 사례를 5~10개만 보고 패턴을 정확히 배우기는 어려운 것과 같은 이치입니다.

그래서 다음 단계는 **학습 방식을 더 만지는 게 아니라, 부족한 카테고리에 한해서만 GPT(OpenAI API)로 학습 문장을 추가로 생성해서 데이터 양 자체를 늘리는 것(표적 증강)**입니다. 전체 데이터셋을 다시 만드는 게 아니라, 이번 테스트로 정확히 확인된 아래 우선순위 카테고리만 집중 보강하면 됩니다.

**표적 증강 우선순위 (이번 테스트에서 확인된 하위 15개)**:

- 식/음료 계열: 직무 공통(자기소개서), 조리사(자기소개서), 카페·레스토랑매니저(역량 부족/취업 진로)
- 디자인 계열: 시각디자이너(취업 진로/역량 부족), 공간디자이너(역량 부족), 편집디자이너(취업 진로), 캐릭터디자이너(취업 진로/역량 부족), 제품디자이너(면접 준비), 직무 공통(자기소개서)
- 그 외: MD/상품기획(온라인마케터·직무공통, 역량 부족), IT/SW 직무 공통(면접 준비)

## 6. 지금 단계에서 팀 발표/보고서에 뭐라고 말해도 되는가

- **대분류 단위 추천은 지금 모델로 자신 있게 사용 가능** (95~96%대)
- **중분류(72%)는 "실사용 가능하지만 개선 진행 중"으로 정직하게 설명**
- **148개 세부 조합, 특히 식/음료·디자인은 아직 보수적으로 취급** — 확정적으로 추천하기보다 "관련 세부 직무 예시" 정도로만 노출하는 게 안전
- 정량 결과(이 표들)와 실제 대화 데모(정성적 확인) 둘 다 발표 자료에 넣기
